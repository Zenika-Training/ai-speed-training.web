Glossaire ​

Agent de code ​

Agent qui lit, modifie et exécute du code dans un dépôt (Copilot, Claude Code, Codex, Cursor…).

Boucle agentique ​

Le cycle demande → le modèle choisit un tool → le harness l'exécute → le résultat entre dans le contexte → on recommence si besoin.

CI (intégration continue) ​

Les vérifications lancées automatiquement à chaque changement du code (construire, tester) avant qu'il parte en production.

Context window ​

Tout ce que le modèle « voit » au moment de répondre : consignes, historique, pièces jointes, résultats des tools.

Contrat de modèle ​

Les colonnes et les types qu'un modèle dbt s'engage à fournir. Appliqué (enforced), il fait échouer le build plutôt que de casser en silence ce qui lit le modèle.

Couche sémantique (semantic layer) ​

L'endroit où les métriques sont définies une seule fois, au-dessus des modèles, et interrogées par tous les outils (dbt Semantic Layer avec MetricFlow, Cube, LookML).

Data owner ​

La personne du métier qui répond d'une donnée ou d'un KPI : sa définition, sa qualité attendue. Une seule par KPI.

dbt ​

Outil qui transforme les données dans l'entrepôt avec des requêtes SQL versionnées (les modèles), les teste et les documente.

DuckDB ​

Moteur de base de données analytique qui tourne dans un fichier local, sans serveur : celui du pipeline de l'atelier.

Exposition (exposure) ​

La déclaration, dans dbt, d'un usage en aval (un tableau de bord, une page BI) et de ce dont il dépend : le lignage va jusqu'à l'écran.

Grain ​

Ce que représente une ligne d'une table (« une ligne par séjour », « une ligne par paiement »). Un grain flou donne des chiffres qui changent selon qui les calcule.

Harness ​

Tout le logiciel autour du modèle : consignes, mémoire, tools, enchaînement des étapes. Deux assistants sur le même modèle diffèrent par leur harness.

Human-in-the-loop ​

Un humain qualifié valide la sortie de l'IA avant qu'elle soit utilisée.

Instructions projet ​

Fichier versionné dans le dépôt, chargé à chaque session : conventions, commandes, pièges (AGENTS.md, CLAUDE.md pour Claude Code). C'est l'équivalent dev des instructions personnalisées.

KPI ​

Indicateur clé de performance : un chiffre suivi pour piloter, avec une définition écrite et une personne qui en répond.

Lignage (lineage) ​

Le chemin d'une donnée, de sa source aux tableaux de bord qui l'utilisent. Il dit où chercher quand un chiffre est faux, et ce qu'un changement va toucher.

Mart ​

La couche de modèles destinée aux usages (BI, analystes) : des tables orientées métier, aux noms compréhensibles.

Mesure non additive ​

Un compte de distincts (membres, clients) ne s'additionne pas d'une ligne à l'autre : la même personne peut figurer sur plusieurs lignes. Le total se calcule au bon grain.

MetricFlow ​

Le moteur de la couche sémantique de dbt : il lit les semantic models et les métriques, et génère le SQL d'une requête (mf query).

Métrique ​

Un KPI implémenté dans la couche sémantique : une mesure, un filtre, une description ; on l'interroge par dimensions sans réécrire de SQL.

Modèle intermédiaire ​

Une couche entre le staging et les marts : une logique réutilisable (les séjours terminés, les membres actifs) écrite une seule fois.

Permissions ​

Les actions autorisées à l'agent (lire, écrire, lancer une commande, accéder au réseau).

Pull request (PR) ​

Une proposition de changement sur une branche, relue avant d'être fusionnée. La revue regarde aussi ce que le changement casse en aval.

Restructuration (refactoring) ​

Changer la structure du code sans changer ce qu'il produit. Elle se prouve en comparant la sortie avant et après.

Saved query ​

Une requête de la couche sémantique enregistrée (métriques, dimensions, grain), réutilisable et exportable, par exemple pour alimenter une page BI.

Session ​

Une conversation ; elle accumule du contexte, utile ou parasite.

Staging ​

La première couche de modèles : la source renommée, typée et nettoyée, une vue par source, sans règle métier.

Test de données ​

Une règle vérifiée sur les données elles-mêmes (unicité, valeurs permises, référentiel) à chaque construction.

Token ​

Morceau de mot traité par le modèle ; c'est aussi l'unité de facturation (≈ ¾ de mot en anglais).

Tools ​

Capacités que le modèle peut appeler pendant sa réponse : recherche web, calcul, lecture de fichiers, Jira, Figma… (tool calling).

Version de modèle ​

Deux versions d'un même modèle dbt servies en parallèle, pour changer une colonne sans casser ceux qui lisent l'ancienne, avec une date de fin.
