L'IA au quotidien de l'Analytics Engineer

Un atelier dans ton terminal, sur des modèles dbt fictifs et leur couche sémantique. Environ 3 h 10, en sept modules sur les modèles analytiques de l'équipe Phare (dbt, DuckDB et MetricFlow, tout en local) : trois chiffres pour un même KPI, une définition à poser avec le métier puis à implémenter une seule fois, un mart à remettre en couches sans qu'un chiffre bouge, une pull request à relire, un contrat et une version pour ne pas casser un tableau de bord, un jeu de données pour la BI, une question d'analyste. L'agent de code fait le mécanique ; toi tu définis, tu prouves et tu décides.

Atelier Analytics Engineer : un KPI, une définition, des modèles qui tiennent

Analytics Engineers (ou data analysts et data engineers qui en font le métier) : modèles dbt, KPI, BI, et déjà la pratique d'un agent de code.

Prérequis : Le module 1 « L'IA au quotidien du développeur », ou la même pratique d'un agent de code. Claude Code installé et ton accès ouvert ; uv (il installe Python, dbt, DuckDB et MetricFlow) ; git ; un terminal bash ou zsh (sous Windows, Git Bash).

  • M0Démarrer l'atelier dans ton terminal10 min

Le projet et ses données sont fictifs : tu peux les donner à l'agent sans risque. Sur tes vrais modèles, le schéma ou un agrégat plutôt que des lignes de production, et seulement dans l'outil autorisé.

Ta progression sur ce site reste dans ce navigateur ; celle de l'atelier reste dans ton terminal. Rien n'est transmis à personne.
