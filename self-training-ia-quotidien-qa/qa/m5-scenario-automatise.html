La mission

Mission 5 · Les cas de test manuels sont prêts à être rejoués

« J'ai fait générer le scénario du départ express, et tout est vert. Tu relis avant que je l'ajoute à la campagne automatique ? »

Théo, relecture et accompagnement technique

Pourquoi l'IA ici

  • Rejouer vite : un cas manuel devient un scénario relié à du code.
  • Lisible n'est pas fiable : un scénario peut tout faire et ne rien vérifier.
  • Pourquoi l'IA ici : elle écrit vite et propre ; c'est toi qui dis ce que le test vérifie vraiment.

L'IA et toi

L'IA fait

  • Traduit un cas en scénario Gherkin
  • Écrit le code des étapes
  • Explique le code en français

✋Toi, tu

  • lis ce que chaque étape vérifie
  • compares au cas d'origine
  • acceptes ou refuses dans le patrimoine

  1. 🎭Rôle

    Tu es QA automaticien·ne. Tu relis des tests générés comme un test que tu devrais maintenir pendant des années.

    💡 Le rôle fixe l'exigence : relire pour le long terme, pas pour que « ça tourne ».

  2. 📎Contexte

    Je suis QA de l'application Lanterne. Je joins mes cas de test manuels du départ express (CT-01 à CT-04) et le scénario Gherkin avec son code, générés par une IA sans relecture.

    💡 Les cas sont la référence ; le scénario est ce qu'on juge.

  3. 🎯Tâche

    Fais une revue, étape par étape : 1. pour chaque étape « Alors », dis en une phrase, en français, ce qu'elle vérifie réellement ; 2. repère toute étape qui ne vérifie rien, qui réussit quoi qu'il arrive, ou qui attend une durée fixe ; 3. compare avec les cas de test : quel résultat attendu n'est pas vérifié, quel cas n'a pas de scénario ; 4. pour chaque défaut, propose une correction en une ligne.

    💡 « Ce qu'elle vérifie réellement » force l'IA à lire le code au lieu de le trouver propre ; la comparaison aux cas fait ressortir l'oubli.

  4. 📐Format

    Un tableau : étape ou ligne / ce qu'elle vérifie / défaut éventuel / correction en une ligne. Puis la liste des cas sans scénario.

    💡 Le tableau suit le scénario dans l'ordre, donc tu relis dans le même ordre.

  5. 🛡️Règles

    Règles : - cite l'étape ou la ligne concernée ; - n'ajoute aucun cas qui n'est pas dans mes documents ; - ne réécris pas tout le test : liste d'abord les défauts.

    💡 Une revue précise, sans cas inventé ; tu décides ensuite de ce qui est corrigé.

📎 Avant d'envoyer, joins les documents de l'exercice, plus haut : trombone, glisser-déposer ou « Copier le contenu ».

Checkpoint

Quelle étape du scénario généré ne vérifie rien, et que devrait-elle vérifier ?

Ajouter le résultat obtenu dans ton outil d'IA (facultatif)
Ta réponse reste dans ce navigateur. Le corrigé est à l'étape suivante.

Corrigé

Note d'abord ta réponse au checkpoint, à l'étape précédente : le corrigé t'apprend plus quand tu as déjà cherché.

L'essentiel

Tu n'acceptes pas le fichier tel quel. Trois défauts dans le test et un trou dans la couverture : le paiement n'est jamais vérifié (CT-01), une attente fixe de 5 secondes, un test qui passe toujours (CT-02), et CT-04 sans scénario.

Les quatre points et la décision
  1. Le paiement n'est jamais vérifié (CT-01) : l'étape le paiement est enregistré ne contient qu'un commentaire. Elle devrait contrôler que 248,50 € sont encaissés (par exemple la capture chez le prestataire de test).
  2. Une attente fixe de 5 secondes : waitForTimeout(5000) ralentit chaque lancement et fait échouer le test au hasard (il est flaky). Attends un résultat (le message, l'élément), pas une durée.
  3. Un test qui passe toujours (CT-02) : expect(true).toBe(true) réussit quoi qu'il arrive. Il devrait vérifier le message « Réglez votre note au comptoir », l'absence d'encaissement et la chambre non libérée.
  4. CT-04 (groupe) n'a aucun scénario : le cas a disparu sans le dire, et tout est vert.

Ce qui est bon : CT-03 vérifie son message, la chambre est libérée interroge le PMS, les étapes sont réutilisables.

Décision : tu fais corriger 1 à 3 et ajouter CT-04, puis tu relis de nouveau avant la campagne.

Les pièges

  • ✕Étape qui fait tout et ne vérifie rien
  • ✕Attente de 5 secondes « pour être sûr »
  • ✕« La page s'affiche » toujours vert
  • ✕CT-04 disparu, tout est vert

Équipe ton assistant : Playwright (facultatif)

Un réglage, une fois pour toutes : ton assistant pilote un navigateur pour dérouler un cas. Procédure vérifiée dans la documentation officielle de Playwright MCP ; les menus de Claude Desktop évoluent et dépendent de ton entreprise.

Équipe ton assistant · Claude Desktop

Un navigateur à portée de l'assistant

Un serveur MCP est un branchement standard qui donne à ton assistant de nouveaux outils. Celui de Playwright lui permet de piloter un vrai navigateur et d'exécuter ton parcours de test. Facultatif : le module n'en dépend pas.

  1. 1

    Prépare Node.js

    Il te faut Node.js 18 ou plus (commande node --version). En entreprise, vérifie d'abord que tu peux installer un outil local.

  2. 2

    Ouvre la configuration de Claude Desktop

    Settings › Developer › Edit Config : le fichier claude_desktop_config.json s'ouvre dans ton éditeur. Vérifie dans ton application : les menus changent d'une version à l'autre (guide MCP de Claude Desktop ci-dessous).

  3. 3

    Déclare le serveur Playwright

    Ajoute ce bloc (c'est la configuration standard de Playwright MCP), enregistre, puis quitte et relance Claude Desktop.

    {
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["@playwright/mcp@latest"]
    }
  }
}
  4. 4

    Demande ton parcours

    Dans une nouvelle conversation, remplace l'adresse par celle de ta préproduction. Uniquement un environnement de test et des cartes de test.

    Ouvre [l'adresse de ma préproduction] avec le navigateur Playwright. Suis le cas CT-02 : séjour de test avec une pré-autorisation de 300,00 €, note de 640,00 €, jour du départ ; ouvre le départ express et confirme le règlement. Décris ce que tu vois à chaque étape et dis si le message « Réglez votre note au comptoir » s'affiche. N'utilise aucune vraie donnée.

Ça a marché si… L'assistant ouvre le navigateur, déroule les étapes et te dit ce qu'il constate. Relis son compte rendu contre le résultat attendu du cas : il a pu ne rien vérifier. Le résultat reste un brouillon de test, ta relecture décide.

Ailleurs :Claude Code : claude mcp add playwright npx @playwright/mcp@latest ; VS Code, Cursor et d'autres assistants : le même bloc dans leur configuration MCP.Sans MCP : l'exercice se fait entièrement avec le prompt, sans navigateur.
