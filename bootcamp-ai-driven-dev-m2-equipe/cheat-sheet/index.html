Au bout seul
  • Le mode n'est qu'un défaut : les droits vivent dans un fichier.
  • Une allowlist n'est pas une sandbox : le seul périmètre réel est l'isolation.
  • La policy vit dans le runtime, pas dans le prompt.

Tokens, cache et mémoireCh. 2

  • Mesurer d'abord (/context) ; la dépense se lit ailleurs.
  • KV cache côté serveur (5 min à 24 h) ; expiré, il coûte de l'argent, jamais de la mémoire.
  • Tâche finie → /clear · en cours → /compact.
  • Mémoire : fichier versionné, native, middleware. Aucun standard.
  • RAG sur le code : naïf, AST-aware, knowledge graph (Graphify).

Partager en équipeCh. 7

6 réflexes pour lundi matin

  1. Mesurer sa context window avant d'optimiser.
  2. Mettre la policy dans un hook, pas dans le prompt.
  3. La spec précède la génération de code.
  4. Committer via l'assistant : doc suivie, part d'IA tracée.
  5. Relire le diff avant de valider.
  6. Versionner et partager skills et AGENTS.md.

Mots-clés

Harness tout le code autour du modèle : outils, mémoire, permissions, boucle
Context window tout ce que le modèle voit pendant une génération
Hook action déterministe déclenchée par le harness, quoi que dise le modèle
Skill dossier SKILL.md + scripts, chargé quand la tâche s'y prête
MCP protocole standard pour brancher des outils à l'agent
SDD la spec écrite, source de vérité de la génération
