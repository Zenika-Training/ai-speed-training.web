L'atelier se joue dans ton terminal

Ops

Un agent de code sur une vraie exploitation

  • Le dépôt d'exploitation de Sillage, une API de suivi de colis (fictive) : manifestes Kubernetes, Terraform, CI, logs, métriques, alertes, scripts. Rien n'est relié à une production.
  • Claude Code joue le formateur : il affiche chaque étape, te donne les prompts et commente ce que tu lui rapportes.

Ce site te sert de guide de démarrage. Le cours, lui, tient dans une archive à télécharger.

1. Vérifie ton poste, puis dézippe

Étape 1

Trois outils, rien d'autre

Ni cluster, ni compte cloud, ni Docker : les manifestes se relisent, les logs et les métriques sont des fichiers, les scripts tournent sur un dossier d'exemple.

Ton poste

  • ✓Claude Codeinstallé, accès ouvert
  • ✓gitgit --version
  • ✓bash ou zshsous Windows, Git Bash
sh
claude --version && git --version

Dézippe hors de tout projet, jamais…

  • ✕Dans un projet qui a déjà un CLAUDE.mdClaude Code le chargerait aussi, et le parcours changerait.

2. Lance la session SUPPORT

Ouvre un premier terminal dans ops-workshop/ et lance Claude Code en mode Manual : il te demandera ton accord avant de modifier un fichier ou de lancer une commande.

sh
claude --permission-mode default

Puis écris :

text
Lis le fichier ATELIER-OPS.md et démarre.

3. Ouvre TRAVAIL quand SUPPORT te le demande

Étape 3

Le dépôt des exercices

À l'étape 0.3, ouvre un second terminal, dans ops-workshop/ lui aussi. La session TRAVAIL s'ouvre dans artefacts/sillage-ops, le dépôt d'exploitation fictif : tu peux tout y essayer sans risque, sauf le script que le module M5 te demande justement de ne pas lancer.

SUPPORT te donne ces commandes à l'étape 0.3 : attends-la. Ce bloc te sert surtout à reprendre plus tard.

sh
cd artefacts/sillage-ops
git init -q && git add -A && git commit -qm "Etat initial"
claude --permission-mode default

Ce que tu dois voir

  • ✓Un commit initialpour voir ce que l'agent modifie (git diff), et revenir en arrière
  • ✓manual mode ons'affiche sous la zone de saisie de TRAVAIL
  • ✓/modelun modèle intermédiaire (Sonnet) suffit, dans les deux sessions

4. Le déroulé, et tes commandes

Tes commandes dans SUPPORT

  • NEXTOKpasser à l'étape suivante
  • RÉPÈTEréafficher l'étape en cours
  • OÙ EN SUIS-JEvoir où tu en es
  • RECADREl'IA s'écarte : elle reprend son rôle
  • KOun checkpoint ne passe pas : on regarde pourquoi
  • ALLER M4aller à un module, après confirmation
  • ENGLISHFRANÇAISchanger de langue

5. Reprendre plus tard, et si quelque chose coince

Étape 5

Tu peux t'arrêter à la fin de chaque module

Pour reprendre, relance claude --permission-mode default dans ops-workshop/, puis donne à SUPPORT le module où tu t'étais arrêté. Les modules sont indépendants : chacun part du dépôt tel qu'il est dans l'archive.

text
Lis le fichier ATELIER-OPS.md et va au module M4.

Si quelque chose coince

  • Un checkpoint ne passe pasécris KO dans SUPPORT, ce n'est pas bloquant
  • Le projet est casségit restore . revient au dernier commit ; les modules sont indépendants
  • SUPPORT s'écarte du parcoursécris RECADRE
  • Quota, accès, outils autorisésdemande à ton référent

À retenir

  • SUPPORT guide
  • TRAVAIL lit et propose
  • Toi, tu décides et tu lances

L'archive contient aussi les instructions données à l'IA et les réponses attendues des checkpoints. Rien ne t'empêche de les lire, mais l'atelier n'entraîne ton œil que si tu cherches d'abord.
