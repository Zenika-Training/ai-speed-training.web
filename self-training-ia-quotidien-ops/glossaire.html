Glossaire ​

Agent de code ​

Agent qui lit, modifie et exécute du code dans un dépôt (Copilot, Claude Code, Codex, Cursor…).

Boucle agentique ​

Le cycle demande → le modèle choisit un tool → le harness l'exécute → le résultat entre dans le contexte → on recommence si besoin.

Budget d'erreur ​

Ce que le SLO autorise à échouer sur sa fenêtre : avec 99,5 % de succès sur 30 jours, 0,5 % des requêtes. Une alerte utile sonne quand ce budget se consomme trop vite, pas à chaque erreur.

CI (intégration continue) ​

Les vérifications lancées automatiquement à chaque changement du code (construire, tester) avant qu'il parte en production.

Context window ​

Tout ce que le modèle « voit » au moment de répondre : consignes, historique, pièces jointes, résultats des tools.

CronJob ​

Une tâche planifiée de Kubernetes (un batch lancé à heure fixe). Sans spec.timeZone, son horaire s'entend en général en UTC.

Expand / contract ​

Changer un schéma de base en deux temps : ajouter le nouveau (table, colonne) et faire cohabiter l'ancien, puis supprimer l'ancien dans une version suivante, une fois la nouvelle stable. Chaque étape garde un retour arrière possible.

Fatigue d'alerte ​

Quand trop d'alertes ne demandent aucune action, l'astreinte les acquitte par réflexe, et finit par acquitter aussi la vraie.

Harness ​

Tout le logiciel autour du modèle : consignes, mémoire, tools, enchaînement des étapes. Deux assistants sur le même modèle diffèrent par leur harness.

Human-in-the-loop ​

Un humain qualifié valide la sortie de l'IA avant qu'elle soit utilisée.

IaC (Infrastructure as Code) ​

L'infrastructure décrite dans des fichiers versionnés (Terraform, manifestes Kubernetes) plutôt que configurée à la main : elle se relit, se teste et se revoit comme du code.

Instructions projet ​

Fichier versionné dans le dépôt, chargé à chaque session : conventions, commandes, pièges (AGENTS.md, CLAUDE.md pour Claude Code). C'est l'équivalent dev des instructions personnalisées.

Mode à blanc (dry-run) ​

Un script lancé sans effet : il affiche ce qu'il ferait (les fichiers qu'il supprimerait) sans le faire. Par défaut dans un script qui supprime ; l'action demande une option explicite.

Permissions ​

Les actions autorisées à l'agent (lire, écrire, lancer une commande, accéder au réseau).

Pool de connexions ​

Les connexions à la base qu'un service ouvre d'avance et se partage. Quand toutes sont prises, les requêtes attendent, puis échouent (« pool exhausted »).

Post-mortem sans blâme ​

Le compte rendu d'un incident qui cherche ce qui, dans le système, l'a rendu possible, et pas qui s'est trompé : des faits datés et sourcés, des causes, peu d'actions suivies.

Retour arrière (rollback) ​

Revenir à l'état d'avant un changement. Il se prévoit avant le déploiement : certaines étapes (supprimer une colonne) le rendent impossible.

Rolling update ​

Le remplacement progressif des pods d'un service : pendant quelques minutes, l'ancienne et la nouvelle version tournent ensemble, sur la même base.

Runbook ​

La fiche d'exploitation d'une alerte ou d'un service : le symptôme, ce qu'on vérifie, ce qu'on fait et qui prévenir.

Session ​

Une conversation ; elle accumule du contexte, utile ou parasite.

Signal et bruit ​

Le bruit est présent tout le temps, au même rythme, sans conséquence ; le signal apparaît à un moment précis, souvent juste après un événement (un déploiement, un batch).

SLI, SLO ​

Le SLI est ce qu'on mesure du point de vue de l'utilisateur (part des requêtes en succès, durée) ; le SLO est l'objectif fixé sur ce SLI (99,5 % sur 30 jours).

Token ​

Morceau de mot traité par le modèle ; c'est aussi l'unité de facturation (≈ ¾ de mot en anglais).

Tools ​

Capacités que le modèle peut appeler pendant sa réponse : recherche web, calcul, lecture de fichiers, Jira, Figma… (tool calling).

UTC ​

Le temps universel, sans fuseau. En hiver, 07:45 UTC est 08:45 à Paris : un horaire écrit sans fuseau se vérifie.
