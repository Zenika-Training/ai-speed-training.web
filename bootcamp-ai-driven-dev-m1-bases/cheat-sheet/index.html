Bases du développement agentique

L'IA amplifie le développeur, elle ne le remplace pas. C'est vous qui pilotez.

AI-driven dev, pas vibe coding

Vibe codingCode caché, prototypes d'applis neuves (Replit, Lovable, Bolt).
AI-driven developmentL'IDE reste l'interface, toute appli, legacy compris (Claude Code, Copilot, Cursor…).

Un code aussi proche que possible du vôtre, dont vous restez responsable.

Claude Code : modes de permissionShift+Tab

ModeCe qui demande une validation
defaultTout (fichiers, commandes)
acceptEditsCommandes seulement
planLecture seule : un plan, aucune édition
autoUn classifieur vérifie chaque action

Commencez en plan, validez, puis acceptEdits.

CLAUDE.md : les instructions custom

  • Chargé au début de chaque session : pratiques de code + infos générales sur l'appli.
  • Sous ~200 lignes, des règles vérifiables (« Lance npm test avant chaque commit »).
  • /init génère un point de départ. Portées : projet, perso (~/.claude/), organisation.

Prompts prêts à l'emploi

Architecture en mode plan
À partir de cette spécification, propose : la structure, le schéma de base, les endpoints, les décisions clés et leurs compromis.
N'écris aucun code. Rédige ta proposition dans architecture.md.
Exécuter un plan pas à pas
Lis le plan d'exécution dans docs/…md, exécute la prochaine instruction non cochée, coche-la une fois faite.
Arrête-toi à chaque étape et attends ma validation.
Respecter l'existant
AVANT d'écrire du code : regarde le DELETE /tasks/:id existant, nos opérations en masse, nos patterns de validation et d'erreurs.
N'introduis aucun nouveau pattern ni dépendance.
Tests de caractérisation
Avant de refactorer InvoiceCalculator, génère des tests qui capturent le comportement ACTUEL, peu importe qu'il soit correct : je veux savoir si je change quelque chose par accident.

Règles d'or

1. Relire comme un contributeur inconnuCorrection, cas limites, sécurité, perf, lisibilité, dépendances ?
2. Jamais de refactor sans testsLes tests passent-ils avant et après ?
3. N'activer que les MCP utilesCe serveur sert-il vraiment à ce projet ?
4. Bloquer avant, pas aprèsUn hook PreToolUse (exit 2) protège-t-il .env ?
5. Jamais de clé d'API en durVariables d'environnement ou gestionnaire de secrets ?
