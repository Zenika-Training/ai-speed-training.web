# Handout — Les activités

**Le nouveau PDLC IA — ce qui change pour votre équipe · Zenika · support d'activité**

Les activités de la formation, pour les refaire avec votre équipe : la consigne, le matériel et ce qu'on en retient.

## Ranger dans le Nexus (4 min, optionnelle)

*Module 3 · slide « Activité — Ranger dans le Nexus »*

**Objectif** : placer six informations familières dans le Context Nexus, avec deux coordonnées chacune : un registre (Knowledge, Purpose, Contracts, Process) et un niveau (organisation, programme, équipe).

**Déroulé**

1. Par deux, recopiez la grille vide ci-dessous, ou notez simplement « n° → registre, niveau » (à distance, dans le chat : « 1 → Contracts, organisation »).
2. Placez les six cartes en 2 minutes. Une carte peut aller dans plusieurs cases, ou dans aucune.
3. Correction carte par carte, puis débrief.

**Les cartes** (chez Vélora, groupe hôtelier fictif)

1. « Toutes nos interfaces respectent le niveau WCAG AA. »
2. Le glossaire partagé par les équipes du programme.
3. « Rappel de départ : −x % de départs non annoncés à la réception. »
4. Le runbook « VelNotif ne répond plus ».
5. L'ADR « on passe par VelNotif, pas par un prestataire d'envoi externe ».
6. « Sur un écran de suivi, l'équipe accepte 400 ms de temps de réponse au lieu des 200 ms fixés par le groupe. »

**La grille**

|                  | Knowledge | Purpose | Contracts | Process |
| ---------------- | --------- | ------- | --------- | ------- |
| **Organisation** |           |         |           |         |
| **Programme**    |           |         |           |         |
| **Équipe**       |           |         |           |         |

**Pour vous aider** : le handout « Le Context Nexus », sections « Les quatre registres », « Découper une ADR », « La grille registres × niveaux » et « Étendre, déroger, contredire ».

**À retenir**

* Un registre dit ce qu'est une information ; un niveau dit jusqu'où elle s'applique.
* Une ADR ne se range pas d'un bloc.
* Une équipe ne contredit pas une règle du groupe : elle déroge en le déclarant, avec l'approbation du niveau au-dessus.

**Avec votre équipe** : lesquelles de ces six informations existent déjà par écrit chez vous, à quel niveau, et où ?

## Distribuer les casquettes (8 min)

*Module 4 · slide « Activité — Distribuer les casquettes »*

**Objectif** : nommer un porteur pour chaque casquette de votre équipe, voir qui porte trop, et choisir un levier.

**Déroulé**

1. Notez les membres de votre équipe, avec leurs initiales seulement : on regarde l'équipe, on ne juge personne.
2. Placez un porteur sur chaque casquette (4 minutes, seul).
   * Une personne peut porter plusieurs casquettes.
   * L'Orchestrator peut tourner entre 2 ou 3 personnes : partagez sa charge.
   * Le Decision Guarantor est une seule personne, nommée.
3. Additionnez la charge indicative par personne.
4. Entourez la personne la plus chargée et choisissez un levier : répartir, faire tourner, ou signaler un écart (un profil qui manque).
5. Comparez à deux (2 minutes), puis débrief.

**La grille**

| Casquette                                | Qui ? | Charge indicative |
| ---------------------------------------- | ----- | ----------------- |
| Context Engineer                         |       | ~0,25 ETP         |
| Specification Engineer                   |       | ~0,35 ETP         |
| Agentic Workflow Orchestrator            |       | ~0,3 ETP          |
| Decision Guarantor                       |       | ~0,15 ETP         |
| Notre contact Evaluation Engineer (pool) |       | —                 |

**Pour vous aider** : le handout « Équipe et nouveaux rôles », sections « Les quatre casquettes de l'équipe » et « Le premier goulot à repérer ».

**À retenir**

* Nommer les casquettes avant que l'outillage n'arrive : sinon, ce sont les outils qui décident qui fait quoi.
* La première surcharge est souvent la personne la plus sollicitée aujourd'hui.
* Une casquette que personne ne peut porter est un écart à remonter, pas une faute.

**Avec votre équipe** : refaites la grille ensemble, et demandez à chaque personne si sa charge lui paraît réaliste.

## Gain ou pas ? (3 min)

*Module 6 · slide « Exercice éclair — Gain ou pas ? »*

**Objectif** : lire des indicateurs comme un manager, la vitesse avec la qualité, le coût et l'expérience, sans conclure trop vite.

**Déroulé**

1. Lisez les trois équipes, comparées à leur mesure de référence.
2. Pour chacune, tranchez : « oui », « pas encore » ou « attendre » (à distance, dans le chat : « A … , B … , C … »).
3. Correction, puis débrief.

**Les trois équipes**

| Équipe | Ce qu'on observe, par rapport à la référence                                     |
| ------ | -------------------------------------------------------------------------------- |
| **A**  | Lead time −25 % ; taux de reprise +40 %                                          |
| **B**  | Lead time +10 % au deuxième mois ; bugs stables ; enquête d'expérience en hausse |
| **C**  | Complexité livrée +15 % ; bugs stables ; coût IA par point en baisse             |

**Pour vous aider** : le handout « Déploiement et mesure », sections « Mesurer la valeur, pas l'adoption », « Les sept indicateurs » et « La courbe en J ».

**À retenir**

* Une vitesse ne se lit jamais seule : la qualité et le coût vont avec.
* Une baisse au début est attendue ; une baisse qui dure est un signal.
* Sans mesure de référence prise avant l'outillage, aucun gain ne se démontre.

**Avec votre équipe** : quelle donnée vous manquerait aujourd'hui pour trancher ?
