Data Engineer

Un agent de code sur un vrai pipeline

  • Le pipeline de l'équipe Phare (fictive) : dbt sur DuckDB, il tourne entièrement sur ton poste, sans cloud ni compte.
  • Claude Code joue le formateur : il affiche chaque étape, te donne les prompts et commente ce que tu lui rapportes.

Ce site te sert de guide de démarrage. Le cours, lui, tient dans une archive à télécharger.

1. Vérifie ton poste, puis dézippe

Étape 1

Quatre outils, rien d'autre

uv installe lui-même Python 3.12, dbt et DuckDB dans le projet : tu n'as rien d'autre à installer.

Ton poste

  • ✓Claude Codeinstallé, accès ouvert
  • ✓uvinstalle Python 3.12, dbt et DuckDB
  • ✓gitgit --version
  • ✓bash ou zshsous Windows, Git Bash
sh
claude --version && uv --version && git --version

Pas de uv ? Il s'installe en une commande : voir la documentation de uv.

Sans rien installer : avec Docker et VS Code (extension Dev Containers), ouvre le dossier dézippé et choisis « Reopen in Container ». Le devcontainer installe uv, git et Claude Code, et prépare l'environnement du projet. Le détail est dans COMMENCER-ICI.md.

Dézippe hors de tout projet, jamais…

  • ✕Dans un projet qui a déjà un CLAUDE.mdClaude Code le chargerait aussi, et le parcours changerait.

2. Lance la session SUPPORT

Ouvre un premier terminal dans data-engineer-workshop/ et lance Claude Code en mode Manual : il te demandera ton accord avant de modifier un fichier ou de lancer une commande.

sh
claude --permission-mode default

Puis écris :

text
Lis le fichier ATELIER-DATA-ENGINEER.md et démarre.

3. Ouvre TRAVAIL quand SUPPORT te le demande

Étape 3

Le projet des exercices

À l'étape 0.3, ouvre un second terminal, dans data-engineer-workshop/ lui aussi. La session TRAVAIL s'ouvre dans artefacts/phare-pipeline, le pipeline fictif du tableau de bord du départ express : tu peux tout y essayer sans risque.

SUPPORT te donne ces commandes à l'étape 0.3 : attends-la. Ce bloc te sert surtout à reprendre plus tard.

sh
cd artefacts/phare-pipeline
git init -q && git add -A && git commit -qm "Etat initial"
uv sync
uv run dbt seed
claude --permission-mode default

Ce que tu dois voir

  • ✓Une à deux minutesle premier uv sync installe Python, dbt et DuckDB dans .venv
  • ✓Un commit initialpour voir ce que l'agent modifie (git diff), et revenir en arrière
  • ✓manual mode ons'affiche sous la zone de saisie de TRAVAIL
  • ✓/modelun modèle intermédiaire (Sonnet) suffit, dans les deux sessions

4. Le déroulé, et tes commandes

Tes commandes dans SUPPORT

  • NEXTOKpasser à l'étape suivante
  • RÉPÈTEréafficher l'étape en cours
  • OÙ EN SUIS-JEvoir où tu en es
  • RECADREl'IA s'écarte : elle reprend son rôle
  • KOun checkpoint ne passe pas : on regarde pourquoi
  • ALLER M4aller à un module, après confirmation
  • ENGLISHFRANÇAISchanger de langue

5. Reprendre plus tard, et si quelque chose coince

Étape 5

Tu peux t'arrêter à la fin de chaque module

Pour reprendre, relance claude --permission-mode default dans data-engineer-workshop/, puis donne à SUPPORT le module où tu t'étais arrêté.

text
Lis le fichier ATELIER-DATA-ENGINEER.md et va au module M4.

Si quelque chose coince

  • Un checkpoint ne passe pasécris KO dans SUPPORT, ce n'est pas bloquant
  • Tu as sauté un moduleson étape « Rattrapage » te remet sur un projet corrigé
  • uv sync échouevérifie l'accès à PyPI (ou au miroir de ton entreprise)
  • SUPPORT s'écarte du parcoursécris RECADRE
  • Quota, accès, outils autorisésdemande à ton référent

À retenir

  • SUPPORT guide
  • TRAVAIL exécute
  • Toi, tu décides et tu prouves
