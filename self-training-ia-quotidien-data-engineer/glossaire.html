Glossaire ​

Agent de code ​

Agent qui lit, modifie et exécute du code dans un dépôt (Copilot, Claude Code, Codex, Cursor…).

Backfill (rattrapage) ​

Recharger des journées passées d'un pipeline, après un incident ou un changement de calcul. Il n'est sûr que si le chargement est idempotent.

Boucle agentique ​

Le cycle demande → le modèle choisit un tool → le harness l'exécute → le résultat entre dans le contexte → on recommence si besoin.

CI (intégration continue) ​

Les vérifications lancées automatiquement à chaque changement du code (construire, tester) avant qu'il parte en production.

Context window ​

Tout ce que le modèle « voit » au moment de répondre : consignes, historique, pièces jointes, résultats des tools.

Contrat de données ​

L'accord écrit entre l'équipe qui produit une donnée et celles qui la consomment : colonnes, formats, fréquence, et comment un changement est annoncé.

dbt ​

Outil qui transforme les données dans l'entrepôt avec des requêtes SQL versionnées (les modèles), les teste et les documente.

DuckDB ​

Moteur de base de données analytique qui tourne dans un fichier local, sans serveur : celui du pipeline de l'atelier.

Grain ​

Ce que représente une ligne d'une table (« une ligne par séjour », « une ligne par paiement »). Un grain flou donne des chiffres qui changent selon qui les calcule.

Harness ​

Tout le logiciel autour du modèle : consignes, mémoire, tools, enchaînement des étapes. Deux assistants sur le même modèle diffèrent par leur harness.

Human-in-the-loop ​

Un humain qualifié valide la sortie de l'IA avant qu'elle soit utilisée.

Idempotence ​

Un traitement est idempotent quand le relancer donne le même résultat : une relance après incident ne crée pas de doublons.

Instructions projet ​

Fichier versionné dans le dépôt, chargé à chaque session : conventions, commandes, pièges (AGENTS.md, CLAUDE.md pour Claude Code). C'est l'équivalent dev des instructions personnalisées.

Jointure qui multiplie les lignes (fan-out) ​

Une jointure vers une table qui a plusieurs lignes par clé : chaque ligne de départ est répétée, et les comptages gonflent.

Lignage (lineage) ​

Le chemin d'une donnée, de sa source aux tableaux de bord qui l'utilisent. Il dit où chercher quand un chiffre est faux, et ce qu'un changement va toucher.

Modèle incrémental ​

Un modèle dbt qui n'ajoute ou ne remplace que les nouvelles données à chaque exécution, au lieu de tout reconstruire.

Permissions ​

Les actions autorisées à l'agent (lire, écrire, lancer une commande, accéder au réseau).

Profilage ​

Décrire une source avant de l'utiliser : types, valeurs vides, valeurs distinctes, minimum et maximum, doublons, unités, fuseaux.

Runbook ​

La fiche d'exploitation d'un pipeline : comment il tourne, et pour chaque incident connu, le symptôme, la vérification, quoi faire et qui prévenir.

Schéma en étoile ​

Une table de faits (les événements à compter, à un grain donné) entourée de tables de dimensions (hôtel, date…) qui servent à filtrer et regrouper.

Session ​

Une conversation ; elle accumule du contexte, utile ou parasite.

Staging ​

La première couche de modèles : la source renommée, typée et nettoyée, une vue par source, sans règle métier.

Test de données ​

Une règle vérifiée sur les données elles-mêmes (unicité, valeurs permises, référentiel) à chaque construction.

Test unitaire (dbt) ​

Un test qui donne au modèle des données d'entrée écrites à la main et compare sa sortie à celle attendue : il vérifie le code, pas les données.

Token ​

Morceau de mot traité par le modèle ; c'est aussi l'unité de facturation (≈ ¾ de mot en anglais).

Tools ​

Capacités que le modèle peut appeler pendant sa réponse : recherche web, calcul, lecture de fichiers, Jira, Figma… (tool calling).

UTC ​

Le temps universel, sans fuseau. Un horodatage en UTC tombe parfois un autre jour qu'en heure de Paris : on le convertit avant de regrouper par jour.
