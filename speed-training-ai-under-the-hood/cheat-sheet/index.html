Ce qui se passe dans le modèle

Le modèle prédit, le harness agit, la gateway gouverne.

Six notions

LLM le moteur : prédit le token suivant
SLM le petit moteur : 1 à ~15 Md de paramètres
Agent modèle + outils + boucle + objectif
Harness tout le code qui n'est pas le modèle
Orchestrateur coordonne plusieurs agents
SDD la spec écrite, source de vérité

La pile complète

Méthode SDD : spec → plan → tâches
Orchestrateur : découpe, distribue, agrège
Agents = harness + appel au modèle ⇄ outils, MCP
Gateway + guardrails : auth, routage, quotas, logs
Fournisseurs : cloud, hyperscaler, souverain, SLM local

Les outils sont exécutés par le harness, jamais par le modèle.

Tirage
  • Un token à la fois : 500 tokens de réponse = 500 passes.
  • Attention : les tokens se lisent entre eux ; MLP : les connaissances.
  • Température basse = favori ; top-p = tirage parmi les plus probables.
  • Il produit du plausible, pas du vrai.

Contexte et KV cache

  • Sans état : à chaque tour, le harness renvoie tout le contexte.
  • Plus long ≠ mieux : lost in the middle, context rot.
Prefilllit le prompt en parallèle → temps avant le 1er token
Decodeun token par passe, réutilise le cache → tokens/s

Prompt caching : préfixe déjà vu facturé jusqu'à ~90 % moins cher. Gardez le début stable.

Rendre un modèle plus léger

  • Quantification : un 8B passe de 16 Go (FP16) à ~5 Go (4 bits).
  • Distillation : un petit élève imite un grand professeur.
  • MoE : DeepSeek-V3, 671 Md au total, 37 Md actifs par token.

6 réflexes de développeur

  1. Compter en tokens : coût, limites, latence.
  2. Demander des sorties courtes et des diffs.
  3. Mettre l'info utile dans le contexte.
  4. Garder le préfixe stable en session.
  5. Vérifier : tests, typage, revue.
  6. SLM pour trier, LLM pour raisonner.

Agents, harness et sécurité

Le modèle n'exécute rien : il écrit une demande d'action.

Les étapes en pointillé se répètent : 5 à 20 tours pour une tâche simple. stop_reason: "tool_use" (Anthropic), finish_reason: "tool_calls" (OpenAI).

Tool calling

① harness déclare l'outil
   { name, description, input_schema }
② modèle demande
   { type: "tool_use", name, input }
③ harness exécute et répond
   { type: "tool_result", content }

Le modèle choisit sur la description, envoyée en tokens à chaque tour : soignez-la, c'est un prompt.

Mémoire : quatre étages

  1. Context window : la conversation, limitée.
  2. Compaction : le harness résume l'historique.
  3. Fichiers : AGENTS.md, notes, plans.
  4. Recherche : grep, RAG, MCP, à la demande.
MCPconnecte un agent à des outils
A2Aconnecte des agents entre eux

Le harness

Boucle · outils · contexte · permissions (allow / ask / deny, sandbox) · hooks déterministes · sous-agents · observabilité.

Même modèle, deux harness : résultats et coûts très différents.

Comment un agent déraille

  • Boucle sans fin → limite de tours.
  • Faux succès → vérification indépendante.
  • Explosion de coût → budget par tâche, gateway.
  • Injection indirecte → droits minimaux.

Guardrails

Trio létal : données privées + contenu non fiable + sortie réseauCassez au moins une des trois branches.

Gardes d'entrée et de sortie : elles réduisent le risque. Garde d'action (permissions, sandbox) : elle le borne.
