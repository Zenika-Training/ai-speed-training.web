Comprendre un LLM et un agent

Un contexte clair + des instructions précises + des données fiables = une IA utile et de confiance.

Mécanique des LLM

  • Tokens : le texte est découpé en tokens (~0,75 mot en français), unité de mémoire et de facturation.
  • Probabilités : à chaque étape, le token suivant le plus probable. Le LLM ne comprend pas au sens humain.
  • Température : le degré d'aléa, basse pour le code, haute pour la créativité. Top-p : on se restreint aux p % de masse de probabilité.

Deux prompts identiques, deux réponses différentes : c'est une fonctionnalité, pas un bug.

Mémoire de travail

Context windowprompt + historique + pièces jointes + réponse ; 1M tokens pour Sonnet 4.6, mais précision et coût se dégradent bien avant
Compressionla fenêtre sature : les anciens échanges sont résumés, on perd les détails
Lost in the middlele modèle retient mieux le début et la fin (courbe en U)

Critique au début et à la fin, documents importants en premier, missions découpées, « résume ce qu'on a fait, et continue ». La « mémoire » d'un assistant est une répétition dans le prompt : le LLM n'est jamais modifié.

Réponse

Le programme n'interroge pas directement le LLM : il lui signale les outils disponibles et exécute ses appels. Trois accès : RAG et données locales, outils via MCP, réalisation d'actions.

Embeddings et RAG

Embedding : un texte devient un vecteur ; proches par le sens = proches dans l'espace (« bug en prod » ≈ « incident critique »).

Règles d'utilisation

  • Une IA contractualisée : Zero-Data Retention et confidentialité garanties.
  • Tout autre outil : demander à la DSI. Sinon, c'est du Shadow AI.

Les 4 rails d'une IA utile

  1. Contexte : Projects pour persister, pièces jointes pour ponctuel, RAG pour la masse.
  2. Instructions : Persona, Tâche, Format, Contexte ; balises XML ; critiques en haut et en bas.
  3. Modèle et réglages : Haiku vitesse, Sonnet par défaut, Opus raisonner ; température basse pour le code.
  4. Vérification : citations (RAG), relire le diff (Claude Code), hallucination, règle DSI.

Project ou Skill ?

Projectun contexte : « tout sur le client X »
Skillune compétence : « comment rédiger un CR chez nous »

Les deux se combinent et se partagent dans une Team Anthropic. Une Skill est chargée automatiquement.

Mots-clés

Token morceau de mot, unité de calcul et de facturation
Context window tout ce que le modèle voit en une requête
Lost in the middle le milieu d'un long contexte est moins bien exploité
Embedding texte projeté en vecteur de sens
RAG ancrer la réponse dans vos documents
MCP protocole standard pour brancher un outil externe
Skill dossier SKILL.md qui emballe un savoir-faire
Shadow AI outil d'IA non validé par l'entreprise
Zero-Data Retention données non réutilisées pour l'entraînement
