L'IA dans le quotidien du Data Scientist

L'IA écrit le code et prépare. La cible, les variables, la métrique, ce qu'on dit au comité : c'est toi.

Parcours Data Scientistà retenir, mission par mission

  • Cadrer : la décision avant le modèle ; une cible écrite, avec son horizon. Prédire n'est pas expliquer.
  • Explorer : une affirmation, une cellule qui la montre. Doublons, sentinelles, manquants qui ne sont pas au hasard.
  • Variables : au moment de prédire, cette donnée existera-t-elle ? Un score trop beau est une alerte.
  • Modèles : toujours une baseline ; la métrique de la décision, pas l'accuracy.
  • RAG : une grille avant les réponses ; la source fait foi, pas le LLM juge.
  • Production : surveiller ce qu'on peut mesurer tout de suite ; une rupture a une cause datée.
  • Restituer : le gain chiffré, et ce que le modèle ne dit pas, à voix haute.

Dès demain

  • À ton prochain projet, écris la décision que le modèle doit éclairer avant de toucher aux données.
  • Avant chaque restitution, une ligne « ce que le modèle ne dit pas ».

Deux IA différentes

  • Le modèle de machine learning apprend sur tes données et note chaque cas : c'est lui qui prédit.
  • Le LLM écrit le code, relit, résume, rédige, joue ton interlocuteur. Un chiffre qu'il annonce sans l'avoir exécuté est une hypothèse.

Avant de donner une vraie donnée

  1. Quelle sensibilité ? La classification des données de ton entreprise s'applique.
  2. Ai-je besoin des lignes ? Le schéma, un agrégat ou un échantillon synthétique suffit souvent.
  3. Suis-je dans l'outil autorisé ? Notebook en ligne compris.

Ce qui reste ta décision

  • La cible, fixée avec le métier.
  • Les variables que tu peux défendre, et la métrique.
  • Le déploiement d'un assistant, le ré-entraînement d'un modèle.
  • Ce que tu dis au comité, limites comprises.

Les 5 réflexes de toute demande à l'IA

  1. Donne le contexte utile, et seulement lui : tout occupe la context window.
  2. Dis le format : un tableau, un verdict par ligne.
  3. Interdis-lui d'inventer : « non précisé » plutôt qu'un chiffre.
  4. Vérifie en exécutant : une cellule par affirmation.
  5. Décide toi-même : l'IA calcule, tu choisis.

Consignes types et pièges

Prédire n'est pas expliquer.

Consignes typesune nouvelle conversation par tâche, seulement les documents utiles

Relire une exploration
Format :affirmation / ce que montrent les sorties / juste, faux, trompeur.
Règles :seulement des chiffres exécutés ; pour toute cause, cherche un facteur caché.
Chasser les fuites
Format :variable / connue à la date d'export ? / dépend de la cible ? / garder, écarter.
Règles :« à vérifier » plutôt qu'une date inventée.
Comparer des modèles
Format :baseline ; modèles suspects ; métrique de la décision vs hasard ; ce que le modèle rate.
Règles :chaque calcul posé.
Évaluer un RAG
Format :grille de 4 critères ; question / verdict / règle source / type d'erreur.
Règles :juger contre la source seule ; citer la règle.

Pièges vus dans le parcours

  • Une corrélation prise pour une cause (un facteur caché : le niveau).
  • Une valeur sentinelle (999) dans une moyenne.
  • Des manquants qui ne sont pas au hasard.
  • Une fuite : une donnée connue après la prédiction.
  • Une accuracy célébrée sous la baseline.
  • Un LLM juge indulgent avec les réponses plausibles.

Avant de diffuser un résultat

1. Comparé à quoi ?Baseline, hasard, groupe témoin ?
2. Mesurable quand ?Ce chiffre existe-t-il déjà, ou faut-il attendre la cible ?
3. Cause ou corrélation ?Quel test le prouverait ?

Mots-clésglossaire complet sur le site

Baseline le modèle le plus simple, calculé avant tout autre.
Fuite (de la cible) une variable connue seulement après la prédiction.
AUC de 0,5 (hasard) à 1 (parfait) ; 1,00 sur du réel est suspect.
Précision et rappel la part de vrais parmi les désignés ; la part trouvée parmi les vrais.
Dérive les données changent après l'entraînement, le modèle se trompe sans le dire.
RAG l'assistant répond à partir de passages d'une source ; il peut quand même inventer.
