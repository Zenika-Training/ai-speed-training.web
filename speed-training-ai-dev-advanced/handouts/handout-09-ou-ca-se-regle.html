Où ça se règle dans mon outil ​

La formation parle de concepts ; cette fiche donne, pour quatre harness courants, l’endroit où se règlent les primitives de l’Avancé : hooks, sous-agents, permissions et sandbox, instructions projet, skills, MCP, compaction, effort de raisonnement.

Rédigé le 21 octobre 2026 ; les outils changent vite. Les noms de modes, d’événements, les commandes et les chemins bougent d’une version à l’autre : en cas de doute, la documentation du jour fait foi. Cette fiche ne reprend que ce que les supports Zenika sourcent (handout « Où ça se règle » de la Foundation, vérifié sur les docs des éditeurs le 21 octobre 2026 ; bootcamp AI-Driven Development, module 2). « à vérifier dans la doc de l’outil » signale une case non sourcée ; « — » l’absence d’équivalent documenté.

Les formats ouverts passent d’un outil à l’autre : AGENTS.md (instructions projet), SKILL.md (skills) et MCP (tools). Une équipe mixte peut versionner un seul jeu de fichiers, chacun garde son harness. Hooks et sous-agents, eux, n’ont pas de format commun.

  • Les quatre moments génériques de la formation se lisent ainsi : avant un tool = preToolUse / PreToolUse ; après un tool = postToolUse / PostToolUse ; fin de tour = agentStop / Stop ; fin de session = sessionEnd.
  • La « fin de tour » n’est pas un pre-commit : pour contrôler un git commit, visez le hook d’avant un tool sur la commande git, ou un hook git classique.
  • La sortie standard d’un hook ne s’affiche pas : on juge un hook à son effet. Seul le SessionStart de Claude Code réinjecte sa sortie dans le contexte ; Copilot attend un JSON avec un champ additionalContext.

  • Le mode affiché n’est qu’un défaut : une autorisation large en configuration fait que l’agent ne demande plus rien. La configuration a le dernier mot.
  • Codex sépare explicitement les deux réglages de la formation : l’approbation (quand on me demande) et la sandbox (ce que l’agent peut atteindre). Une bonne grille de lecture, quel que soit l’outil.
  • Quand aucune sandbox n’est sourcée pour votre harness, l’isolation reste possible hors de l’outil : conteneur, devcontainer, VM, compte dédié, réseau coupé.
