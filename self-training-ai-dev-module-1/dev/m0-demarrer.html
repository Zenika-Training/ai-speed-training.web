Démarrer le workshop dans ton terminal

Étape 1/0 ·

Le workshop se joue dans ton terminal

Dev Foundation

Pourquoi un workshop dans le terminal

  • Apprendre un agent de code là où tu l'utilises, sur un vrai projet, pas sur des captures.
  • Claude Code joue le formateur : il affiche chaque étape, te donne les prompts et commente ce que tu lui rapportes.

Ce site te sert de guide de démarrage. Le cours, lui, tient dans une archive à télécharger.

1. Vérifie ton poste, puis dézippe

Étape 1

Cinq outils, cinq vérifications

Tout se passe en local : vérifie ton poste avant de commencer, pour ne pas être coupé en plein module.

Ton poste

  • ✓Claude Codeinstallé, accès ouvert
  • ✓Java 21+java -version
  • ✓Maven 3.9+mvn -v
  • ✓gitgit --version
  • ✓bash ou zshsous Windows, Git Bash
sh
claude --version && java -version && mvn -v && git --version

Tu gères tes versions avec SDKMAN! ou mise ? Le mise.toml de l'archive active Java 21 et Maven 3.9.

Sans rien installer : avec Docker et VS Code (extension Dev Containers), ouvre le dossier dézippé et choisis « Reopen in Container ». Le devcontainer de l'archive installe Java, Maven, git et Claude Code, et précharge les dépendances Maven. Le détail est dans COMMENCER-ICI.md.

Dézippe hors de tout projet, jamais…

  • ✕Dans un projet qui a déjà un CLAUDE.mdClaude Code le chargerait aussi, et le parcours changerait.

2. Lance la session SUPPORT

Ouvre un premier terminal dans claude-code-workshop/ et lance Claude Code en mode Manual : il te demandera ton accord avant de modifier un fichier ou de lancer une commande.

sh
claude --permission-mode default

Puis écris :

text
Lis le fichier CLAUDE-CODE-WORKSHOP.md et démarre.

3. Ouvre TRAVAIL quand SUPPORT te le demande

Étape 3

Le projet des exercices

À l'étape 0.3, ouvre un second terminal, dans claude-code-workshop/ lui aussi. La session TRAVAIL s'ouvre dans artefacts/tasks-api, une petite API Java fictive : tu peux tout y essayer sans risque.

SUPPORT te donne ces commandes à l'étape 0.3 : attends-la. Ce bloc te sert surtout à reprendre plus tard.

sh
cd artefacts/tasks-api
git init -q && git add -A && git commit -qm "Etat initial"
mvn -q test
claude --permission-mode default

Ce que tu dois voir

  • ✓Une à deux minutesle premier mvn -q test télécharge les dépendances, sans rien afficher
  • ✓Un commit initialpour voir ce que Claude Code modifie (git diff), et pour le module M3
  • ✓manual mode ons'affiche sous la zone de saisie de TRAVAIL
  • ✓/modelun modèle intermédiaire (Sonnet) suffit, dans les deux sessions

4. Le déroulé, et tes commandes

Tes commandes dans SUPPORT

  • NEXTOKpasser à l'étape suivante
  • RÉPÈTEréafficher l'étape en cours
  • OÙ EN SUIS-JEvoir où tu en es
  • RECADREl'IA s'écarte : elle reprend son rôle
  • KOun checkpoint ne passe pas : on regarde pourquoi
  • ALLER M4aller à un module, après confirmation
  • ENGLISHFRANÇAISchanger de langue
  • INDICESOLUTIONTERMINÉpendant le quiz final

À la fin de M4, puis avant le quiz, SUPPORT te propose /clear suivi d'une phrase de reprise pour alléger la session. C'est facultatif.

5. Reprendre plus tard, et si quelque chose coince

Étape 5

Tu peux t'arrêter à la fin de chaque module

Pour reprendre, relance claude --permission-mode default dans claude-code-workshop/, puis donne à SUPPORT le module où tu t'étais arrêté.

text
Lis le fichier CLAUDE-CODE-WORKSHOP.md et va au module M4.

Si quelque chose coince

  • Un checkpoint ne passe pasécris KO dans SUPPORT, ce n'est pas bloquant
  • mvn ou java introuvablereprends l'étape 1
  • Pas de « manual mode on »/exit, puis relance avec --permission-mode default
  • SUPPORT s'écarte du parcoursécris RECADRE
  • Tes plugins ou hooks perturbentajoute --setting-sources project,local
  • Quota, accès, outils autorisésdemande à ton référent

À retenir

  • SUPPORT guide
  • TRAVAIL exécute
  • Toi, tu approuves chaque action

L'archive contient aussi les instructions données à l'IA et le corrigé du quiz. Rien ne t'empêche de les lire, mais le quiz n'entraîne ton œil que si tu le fais sans regarder.
